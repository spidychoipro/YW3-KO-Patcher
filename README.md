# 요괴워치3 스키야키 한국어 패치 적용기

본편 롬 파일과 업데이트 파일, 두 개를 고르면 제작팀 공식 최신 한글 패치를 확인하고 적용하는 Windows 프로그램입니다.

- 원본은 건드리지 않고 결과 파일을 새로 만듭니다.
- v1.6.0부터 암호화된 본편/업데이트 CIA도 키 파일 없이 선택할 수 있습니다. 필요한 자동 복호화 도구를 처음 한 번 준비하고 복호화·변환·패치·검증을 이어서 수행합니다.
- v1.5.2부터 실행마다 고유한 임시 폴더를 사용하고 그 안의 파일만 정리합니다. 호환 적용한 입력 CCI와 기존 `_YW3_KO_work` 폴더의 사용자 파일은 삭제하지 않습니다.
- 파일 이름이나 지문 검사로 선택을 막지 않습니다. 두 파일을 그냥 고르면 됩니다.
- 패치 파일과 xdelta3는 처음 실행할 때 공식 배포처에서 자동으로 내려받아 캐시합니다.
- CIA로 넣어도 됩니다. 암호화되어 있으면 풀고, CCI가 아니면 CCI로 바꾼 뒤 패치합니다. hshop에서 받은 본편 CIA도 됩니다(본편·설명서·DLP를 카트리지처럼 다시 묶음).
- TMD에 암호화라고 적혀 있어도 실제 내용이 평문인 CIA는 그대로 읽습니다. 예전에 "NCCH 헤더를 찾지 못했습니다"로 막히던 hshop CIA가 여기에 해당합니다.
- 암호화된 CCI도 NCCH 암호(keyX, 시드)가 있으면 풀어서 진행합니다. 지문·키는 앱에 넣지 않고 `keys.txt` / `seeddb.bin`에서만 읽습니다.
- 암호화된 CIA 내용이 여러 개면 하나라도 풀리는 타이틀 키를 찾습니다. 특정 내용만 안 풀리면 키 문제가 아니라 그 내용이 손상된 것으로 알려줍니다.
- 패치 전에 원본의 게임 영역(확장 헤더·평문·로고·ExeFS·RomFS) 해시를 공식 배포본의 manifest와 대조합니다. 다르면 어느 영역이 다른지 알려주고, 암호 플래그만 바꿔 놓은 가짜 복호화 파일은 키가 있으면 다시 풀어 봅니다.
- v1.6.1부터 결과 CCI의 NCSD 선언 크기가 파티션 끝보다 작으면 헤더 크기만 맞춥니다. GodMode9에서 `.3DS`로 인식되지 않고 일반 파일 메뉴만 뜨던 문제가 여기에 해당합니다. 게임 영역과 해시 검증은 그대로 유지합니다.

배포처: <https://github.com/TeamLimRyan/YW3_SUKIYAKI_KOREAN_LOCALIZATION_RELEASE>

## CIA 자동 복호화 (v1.6.0부터)

암호화된 본편 CIA와 업데이트 CIA를 원본 그대로 선택하고 시작을 누르면 됩니다. 키 파일이 없으면 이번에 실파일로 확인한 외부 복호화 경로를 자동 사용합니다. 키 파일을 사용한 내장 CIA 복호화가 실패해도 자동 도구로 다시 시도합니다. 복호화 CCI와 복호화 CIA는 기존처럼 바로 처리합니다.

외부 도구는 [Batch CIA 3DS Decryptor Redux](https://github.com/xxmichibxx/Batch-CIA-3DS-Decryptor-Redux)의 검증한 고정 버전에서 직접 받습니다. `decrypt.exe`, `makerom.exe`, `seeddb.bin`은 앱 EXE나 이 저장소에 재포장하지 않습니다. 실행 전 SHA-256을 확인하고 캐시하므로 처음에는 인터넷 연결이 필요합니다. 배치 스크립트는 실행하지 않습니다.

원본 CIA는 쓰기·삭제가 차단된 상태로 읽습니다. 한글/일본어 파일명은 작업용 이름으로 처리합니다. 본편의 설명서 파티션과 업데이트 버전·콘텐츠 ID를 유지하고, 복호화 후에도 공식 원본/완성본 게임 영역·NCCH 내부 해시와 CIA TMD 검증을 거칩니다. 도구 종료 코드만으로 성공 처리하지 않습니다.

일반적인 본편+업데이트 처리에는 8GB 이상의 여유 공간을 권장합니다. 원본과 저장 위치가 서로 다른 드라이브면 작업용 복사가 필요해 더 많은 공간이 필요할 수 있습니다. 암호화 CCI의 내장 복호화에는 기존과 같이 키/시드가 필요합니다. 이 기능은 게임 실행 검증을 대신하지 않습니다.

## 한글 패치 버전 확인 (v1.5.0부터)

- **한글 패치 시작**을 누르면 제작팀의 최신 정식 GitHub 릴리스를 확인합니다. 적용할 버전은 화면과 진행 기록에 표시됩니다.
- 공식 ZIP의 SHA-256을 확인하고, ZIP 안의 `manifest.json`에서 해당 버전의 패치 파일명·크기·해시, 결과 파일명·크기·해시와 원본 게임 영역 검증 정보를 함께 읽습니다. 같은 배포 형식의 새 버전은 앱을 다시 설치하지 않아도 적용합니다.
- 패키지는 버전과 ZIP 해시별로, 추출한 패치는 버전과 패치 해시별로 캐시합니다. 구버전의 같은 이름 파일과 섞이지 않습니다.
- 최신 확인에 실패하면 화면에 **최신 확인 실패**와 사용할 캐시 버전을 표시합니다. 캐시의 ZIP 무결성을 확인할 수 없으면 중단합니다. 한 번도 버전을 확인한 적이 없으면 기본 지원 v1.01을 사용한다고 명시합니다. 이때 최신이라고 표시하지 않습니다.
- 새 배포에 manifest나 ZIP SHA-256이 없거나 xdelta 형식·원본 프로필을 지원하지 못하면 중단하고 앱 업데이트를 안내합니다. 이 경우 구버전을 대신 적용하지 않습니다.
- 이 기능은 **원본 파일에 새 한글 패치를 적용**하는 기능입니다. 이미 한글 패치한 롬에 덧씌우거나 앱 EXE 자체를 자동 업데이트하는 기능은 아닙니다.

개발 점검: `python tools/test_updates.py`, `python tools/test_format_regressions.py`, `python tools/test_compatibility.py`, `python tools/smoke_test.py`

## 사용법

1. `YW3-KO-Patcher.exe`를 실행합니다.
2. **① 본편 롬**에 일본판 본편 파일을 고릅니다. 복호화 CCI가 가장 빠르고, CIA나 NCCH도 됩니다(자동 변환). 암호화 CCI는 키가 있으면 풀어서 진행합니다.
3. **② 업데이트 파일**에 Update 4.0 CIA를 고릅니다. 암호화되어 있어도 됩니다.
4. **③ 저장 위치**는 본편 롬 옆 `YW3_KO` 폴더로 자동 지정됩니다. 바꾸고 싶으면 **변경**을 누릅니다. 결과 두 개가 합쳐 약 3.5GB이고 변환 임시 파일까지 쓰기 때문에 8GB 이상 남은 드라이브를 권장합니다.
5. **키 파일 (선택)** 칸은 내장 복호화용입니다. 암호화 CIA는 비워 두어도 자동 도구로 처리합니다. 기존 `keys.txt`나 `aes_keys.txt`가 있으면 롬 옆에 두거나 직접 고르면 됩니다. 암호화 CCI의 내장 복호화용 키를 만드는 법은 아래 [keys.txt 만드는 법](#keystxt-만드는-법)을 보세요.
6. 두 파일을 고르면 아래에 "준비 완료"가 뜨고 **한글 패치 시작** 버튼이 켜집니다. 누르고 기다리면 끝납니다. 처음 한 번은 패치 파일(약 79MB)을 내려받느라 조금 더 걸립니다.
7. 끝나면 진행률이 100%가 되고 저장 폴더가 자동으로 열립니다. 그 폴더에 두 파일이 생깁니다.
   - `YW3_Sukiyaki_KO_base.cci` (본편, 약 3.05GB)
   - `YW3_Sukiyaki_KO_update4.cia` (업데이트, 약 187MB)

에뮬레이터(Azahar)에서는 업데이트 CIA를 먼저 설치하고, 그다음 본편 CCI를 실행합니다. 한쪽만 패치하면 번역이 빠집니다.

## 자동 변환 (CIA / NCCH)

고른 파일이 패치 대상과 형식이 다르면 알아서 맞춰 놓고 진행합니다. 변환은 저장 폴더 안 `_YW3_KO_work`에서 하고, 끝나면 지웁니다.

| 넣은 파일 | 하는 일 | 패치 |
|---|---|---|
| 복호화 CCI | 없음 | 바로 |
| 암호화 CCI (NCCH 표준 암호) | NCCH 암호 해제 (keyX 필요) | 변환본으로 |
| 암호화 CCI (시드 암호) | NCCH 암호 해제 (keyX + `seeddb.bin`) | 변환본으로 |
| 복호화 표시만 된 CCI (내용은 암호화) | 확장 헤더/ExeFS/RomFS를 확인한 뒤 키로 다시 복호화 | 변환본으로 |
| 카드 하드웨어 암호 CCI | **지원 안 함** (콘솔에서 덤프해야 함) | 안내하고 멈춤 |
| 복호화 CIA | 내용 전부를 카트리지처럼 CCI로 다시 묶기 | 변환본으로 |
| 암호화 CIA | 키가 없으면 자동 도구로 복호화 → CCI로 묶기 | 변환본으로 |
| NCCH (`.app`/`.cxi`) | CCI로 감싸기 (암호화면 해제) | 변환본으로 |
| 업데이트 CIA (암호화) | 자동 복호화 및 버전·콘텐츠 ID를 유지한 CIA 재구성 | 복호화본으로 |
| 업데이트 CIA (복호화) | 없음 | 바로 |
| 다른 도구로 만든 CCI (뒤가 잘림) | 공식 카트리지 크기까지 0으로 채움 | 변환본으로 |

CIA 안에 본편 말고 설명서·다운로드 플레이 내용이 같이 들어 있으면 그것까지 파티션으로 넣어서 카트리지 덤프와 같은 모양으로 묶습니다. hshop에서 받은 본편 CIA가 이 경우입니다. 설명서나 DLP가 빠진 CIA라면 카트리지 원본 크기까지 뒤를 0으로 채웁니다. 그 구간은 원래 비어 있던 자리라 게임 내용에는 영향이 없습니다.

앱이 풀 수 있는 CCI 암호는 NCCH 표준 암호(AES-CTR)입니다. 카드리더에서 읽을 때 걸리는 SNOW 2.0 + RC4 단계는 콘솔 하드웨어가 있어야 풀리므로, 그런 파일은 GodMode9/Decrypt9로 콘솔에서 `.3ds`(복호화 CCI)로 덤프한 뒤 넣어야 합니다.

암호화 CCI를 풀면 파일 3.2GB를 다시 쓰기 때문에 30초~2분 정도 더 걸립니다(디스크 속도에 따라 다름). 진행률은 같이 올라갑니다.

호환 원본은 헤더·서명·티켓·인증서 차이 때문에 전체 SHA-256이 공식 값과 다를 수 있습니다. v1.5.1부터는 공식 `source_profile`로 원본 게임 영역을 확인한 뒤 호환 적용하고, 결과를 `target_profile`의 영역 크기·SHA-256 및 NCCH 내부 해시와 대조합니다. 업데이트 CIA는 TMD 콘텐츠·목록·상위 해시를 갱신한 뒤 다시 검증합니다. 검증이 실패하면 임시 결과를 삭제하며 원본과 기존 결과를 보존합니다.

패치 창의 시작 오프셋만으로 ExeFS 손상을 판단하지 않습니다. 원본과 결과에서 실제로 다른 게임 영역을 해시로 확인해 안내합니다. 게임 영역이 같아도 배치가 크게 다른 변환본은 호환되지 않을 수 있으며, 결과 검증을 통과한 파일만 저장합니다.

## 내장 복호화용 keys.txt (선택)

암호화된 CIA는 그 타이틀의 타이틀 키가 있어야 내용을 풀 수 있고, 타이틀 키는 3DS 공통 키로 한 번 더 감싸여 있습니다. 암호화된 CCI는 NCCH 키(keyX)로 풀고, 시드 암호가 걸린 타이틀이면 시드도 필요합니다.

`keys.txt` 파일을 만들고 필요한 줄을 넣어 롬 파일과 같은 폴더에 두세요.

```
common: 0123456789abcdef0123456789abcdef
slot0x3DKeyX: 0123456789abcdef0123456789abcdef
common0: 0123456789abcdef0123456789abcdef
slot0x2CKeyX: 0123456789abcdef0123456789abcdef
slot0x18KeyX: 0123456789abcdef0123456789abcdef
```

- 32자리 16진수만 있으면 됩니다. 줄 순서는 상관없고, 필요한 줄만 있으면 됩니다.
- `common`이나 `slot0x3DKey0`처럼 normal key를 바로 적은 줄이 있으면 그걸 먼저 씁니다.
- 덤프 도구가 만든 `common0`~`common5`는 **KeyY**입니다. 이건 그대로 common 키로 쓸 수 없고, `slot0x3DKeyX`와 짝을 맞춰 normal key를 만들어야 합니다. 그래서 요즘 keys.txt는 이렇게 두 줄이 같이 있습니다.

```
slot0x3DKeyX: 617085719b7cfb316df4df2e8362c6e2
common0: D07B337F9CA4385932A2E25723232EB9
```

- `common00`~`common05`나 `slot0x3DKey0`~`slot0x3DKey5`는 normal key를 인덱스별로 적은 형식입니다.
- 어느 키가 맞는지는 CIA 내용이 실제로 NCCH로 풀리는지 확인하고 고릅니다. 티켓이 가리키는 인덱스를 먼저 보고, 안 되면 나머지 후보를 차례로 봅니다.
- `slot0x2CKeyX`는 보통 NCCH(메뉴 정보/ExeFS)용, `slot0x18KeyX`·`slot0x1BKeyX`·`slot0x25KeyX`는 본문용입니다. 앱이 파일 헤더를 보고 어느 슬롯이 필요한지 알려줍니다.
- `keyX18:`, `2c:` 같은 짧은 이름도 읽습니다.
- 시드 암호 파일은 `seeddb.bin`을 롬 옆에 두면 자동으로 읽습니다. `keys.txt`에 한 줄로 넣어도 됩니다.

```
seed_00040000001AF400: 0123456789abcdef0123456789abcdef
```

- `seeddb.bin`과 `keys.txt`에 같은 시드가 있으면 `keys.txt`가 우선합니다. 시드는 헤더의 해시와 맞는지 확인한 뒤에만 씁니다.
- 찾는 순서: 화면의 **키 파일 (선택)** 칸에서 고른 파일 → `YW3KO_KEYS` 환경 변수가 가리키는 파일 → 본편 폴더 → 업데이트 폴더 → 캐시 폴더(`%LOCALAPPDATA%\YW3KoPatcher`)의 `keys.txt` / `aes_keys.txt` / `seeddb.bin`.
- 내장 복호화용 키는 사용자 파일에서 읽습니다. CIA 자동 경로는 위 제작자 도구를 내려받아 실행합니다.
- 암호화 CIA는 키가 없으면 준비 줄에 자동 복호화 안내가 뜹니다. 암호화 CCI는 필요한 키/시드가 없으면 안내하고 중단합니다.

### keys.txt 만드는 법

GodMode9에 들어 있는 Citra용 키 덤프 스크립트를 쓰면 한 번에 뽑힙니다.

1. 3DS에 GodMode9이 설치되어 있어야 합니다. 커펌이 안 되어 있으면 <https://3ds.hacks.guide/godmode9-usage.html> 순서를 먼저 따라 하세요.
2. <https://citra-emu.com/wiki/aes-keys/>에서 `DumpKeys.gm9`를 받아 SD 카드의 `gm9/scripts` 폴더에 넣습니다.
3. 3DS에서 GodMode9을 실행하고 **HOME → Scripts → DumpKeys**를 고릅니다. 최신 펌웨어(11.16/11.17) 기준입니다.
4. SD 카드에 생긴 `gm9/aes_keys.txt`를 PC로 복사합니다.
5. 그 파일을 롬 옆에 `keys.txt` 또는 `aes_keys.txt` 이름으로 두거나, 앱의 **키 파일 (선택)** 칸에서 고릅니다.

`aes_keys.txt` 안에 `slot0x3DKeyX`와 `common0`~`common5`가 같이 들어 있습니다. 앱은 이 두 가지로 normal key를 만들어 암호화된 CIA를 풉니다. 내장 경로에서 `common0`~`common5`만 있고 `slot0x3DKeyX`가 없으면 normal key를 만들 수 없습니다. v1.6.0의 CIA 자동 도구 경로도 사용할 수 있습니다. 앱의 **키 파일 안내** 버튼에도 같은 내용이 있습니다.

SD 카드를 빼기 싫으면 3DS에 `ftpd`를 설치하고 PC에서 FTP로 `aes_keys.txt`만 받아도 됩니다. New 3DS는 무선 microSD 관리로도 접속됩니다. 남의 콘솔에서 뽑은 파일은 이 콘솔의 CIA와 안 맞을 수 있으니 본인 콘솔에서 뽑아 쓰세요.

## 대상 원본

| 역할 | 파일 | 바이트 | SHA-256 |
|---|---|---:|---|
| 본편 | 복호화 CCI, 일본판 v0 | 3270860800 | `d98a9430f3edc0b25fc1a4e0d147d0b976db1b0bdce8e042c50f0e84a738f4d8` |
| 업데이트 | 복호화 CIA, Update 4.0 | 196408320 | `95d5e28eb4920a68bfc3c0ae407a308ddc06a11ab229da3d28cfa4976af58082` |

프로그램이 미리 지문을 검사해서 막지는 않지만, 위 두 원본이 아니면 xdelta3가 중간에 거부합니다. 그때는 "원본이 패치 대상 버전과 다릅니다"라는 안내가 뜨고 결과 파일은 남지 않습니다.

위 표는 기준이 되는 원본입니다. 같은 게임의 다른 형식(CIA, NCCH, 암호화 CIA)을 넣으면 아래 자동 변환을 거쳐 패치합니다. hshop 본편 CIA나 복호화 CCI도 같은 결과가 나옵니다. 변환본이라 헤더가 조금 다른 경우에는 공식 완성본의 게임 영역을 검증한 뒤 저장합니다.

## 파일 자동 판별

파일을 고르면 헤더만 읽어서 컨테이너 종류(CCI/CIA/NCCH), 암호화 여부, 타이틀 ID를 확인하고 입력칸 아래에 짧게 보여줍니다. 이 판별에는 키를 쓰지 않습니다. 암호화된 CIA는 NCCH 헤더가 안 보이므로 티켓/TMD에서 타이틀 ID를 읽습니다.

- 복호화 CCI + 요괴워치3 본편 타이틀 → "✓ 본편: 정상 (복호화 CCI)"
- 복호화 CIA + 요괴워치3 업데이트 타이틀 → "✓ 업데이트: 정상 (복호화 CIA)"
- 암호화된 본편 CIA → "암호화된 CIA예요. 암호를 풀어서 CCI로 바꾼 뒤 패치할게요"
- 암호화된 업데이트 CIA → "암호화된 CIA예요. 암호를 푼 뒤 패치할게요"
- 암호화된 본편 CCI (NCCH 암호) → "암호화된 CCI예요. NCCH 암호를 풀어서 패치할게요"
- 암호화된 본편 CCI (시드 암호) → 같은 안내 + "seeddb.bin도 필요할 수 있어요"
- 본편/업데이트를 바꿔 넣음 → "두 칸을 서로 바꿔 보세요"
- 다른 게임/다른 타이틀 → 타이틀 ID와 함께 경고

경고가 떠도 시작 버튼은 그대로 눌립니다. 선택을 막지 않고, 확인 대화상자도 띄우지 않습니다.

## 참고

- 기준 원본의 결과는 전체 SHA-256, 호환 원본의 결과는 공식 완성본의 게임 영역·NCCH 내부 해시와 CIA TMD를 검증한 뒤 최종 이름으로 바뀝니다. 실패하면 결과를 남기지 않습니다.
- 끝나면 저장 폴더가 자동으로 열리고, 창에도 **저장 폴더 열기** 버튼이 생깁니다.
- **진행 기록 보기**를 누르면 자세한 로그와 **패치 데이터 새로 받기** 버튼이 나옵니다.
- 패치 파일은 재배포가 금지되어 있어 exe에 넣지 않았습니다. 항상 공식 릴리즈에서만 받습니다.
- 내려받은 파일은 `%LOCALAPPDATA%\YW3KoPatcher`에 캐시되고, 프로그램의 **패치 데이터 새로 받기** 버튼으로 지울 수 있습니다.
- 게임 원본·키·펌웨어·세이브는 프로그램이 읽거나 보내지 않습니다. 네트워크는 패치 파일 내려받기에만 씁니다.

## 안 될 때

- **"원본이 패치 대상 버전과 다릅니다"**: 고른 파일이 위 표의 원본이 아닙니다. 복호화된 파일인지, 본편과 업데이트를 바꿔 넣지 않았는지 확인하세요. hshop 본편 CIA는 이 앱이 알아서 변환하니 그대로 넣으면 됩니다. 다른 도구로 CCI를 만들었다면 뒤가 잘린 파일은 앱이 크기를 채워서 진행하고, 헤더 차이도 봐줍니다. 그래도 안 되면 그 도구가 내용을 바꾼 것이니 변환 전 CIA를 그대로 넣어 보세요.
- **"결과 지문이 다릅니다"**: 결과물을 설치하지 말고 원본을 다시 확인하세요. 프로그램이 해당 결과 파일을 지웁니다.
- **"패치 결과가 공식 원본과 달라서 저장하지 않았습니다"**: 변환은 됐는데 게임 내용 일부가 기준 원본과 다릅니다. 다른 지역판이거나 다른 버전일 가능성이 큽니다. 일본판 스키야키 v0인지 확인하세요.
- **"ExeFS 내용이 공식 원본과 다릅니다"**: 실행 코드 영역의 해시가 제작팀 기준 원본과 다릅니다. 다른 버전·수정본·불완전한 복호화 여부를 확인하세요. 창 오프셋만으로 이 오류를 추정하지는 않습니다.
- **"게임 영역 검증을 통과한 호환 결과"**: 전체 파일 해시는 다르지만 공식 완성본의 게임 영역과 내부 해시 검증을 통과한 결과입니다.
- **"CIA의 타이틀 키는 다른 내용에서 확인됐는데, 일부 내용이 NCCH로 나오지 않습니다"**: 키는 맞고 특정 내용만 깨진 경우입니다. `keys.txt`를 다시 뽑을 필요는 없고, 콘솔에서 덤프한 원본 CIA인지 확인한 뒤 다시 덤프해 보세요. 문제가 된 내용 번호도 같이 나옵니다.
- **"CIA의 타이틀 키를 풀지 못했습니다"**: common 키가 없거나 이 파일과 맞지 않습니다. `common0`~`common5`만 넣었다면 그건 KeyY라서 `slot0x3DKeyX`가 같이 있어야 합니다. 안내에 나오는 티켓 common 인덱스와 시도한 후보 수, 키 파일 요약을 확인하세요. 타이틀 키가 평문으로 든 CIA도 시도하지만, 그래도 안 풀리면 콘솔 덤프 원본인지 보세요.
- **"keys.txt가 필요합니다"**: 암호화 CCI 등의 내장 복호화용 키가 필요합니다. v1.6.0에서 암호화 CIA는 키 없이 자동 도구로 처리할 수 있습니다.
- **키 뽑는 법을 모르겠음**: 앱의 **키 파일 안내** 버튼을 누르면 GodMode9에서 `aes_keys.txt`를 뽑는 순서가 나옵니다. SD 카드를 빼기 싫으면 `ftpd`로 PC에 바로 받으면 됩니다.
- **"암호화된 CCI인데 keyX/시드가 없습니다"**: 위 `keys.txt` 형식대로 `slot0x..KeyX` 줄을, 시드 암호면 `seeddb.bin`을 롬 옆에 두세요. 어느 슬롯이 필요한지는 안내에 나옵니다.
- **"시드가 이 CCI와 맞지 않습니다"**: `seeddb.bin`이 이 게임 버전의 시드를 갖고 있지 않습니다. 콘솔에서 뽑은 `seeddb.bin`을 다시 확인하세요.
- **"확장 헤더를 풀었는데 내용이 맞지 않습니다"**: keyX가 틀렸거나 파일이 콘솔 덤프 그대로가 아닙니다. 덤프를 다시 하고, 키 파일의 해당 슬롯 값을 확인하세요.
- **"카드 이미지 암호"**: 카드리더 하드웨어 단계(SNOW 2.0 + RC4)는 콘솔에서만 풀립니다. GodMode9/Decrypt9로 복호화 CCI(`.3ds`)를 뽑아 넣으세요.
- **실행이 안 되고 SmartScreen 경고**: 서명 없는 exe라서 나오는 경고입니다. 정보 → 추가 정보 → 실행.
- **"NCCH 헤더를 찾지 못했습니다" (첫 내용)**: 예전 버전에서 keys.txt의 KeyY를 common 키로 착각할 때 나오던 오류입니다. 지금은 KeyY와 normal key를 구분하고, 실제로 풀리는지 확인한 뒤에만 진행합니다. 그래도 나오면 파일이 손상됐거나 콘솔 덤프 원본이 아닌 경우입니다.
- **내려받기 실패**: 사내망·백신이 GitHub를 막는 경우가 있습니다. `%LOCALAPPDATA%\YW3KoPatcher`를 지우고 다시 시도하거나, 릴리즈 zip을 직접 받아 `%LOCALAPPDATA%\YW3KoPatcher\YW3S_Korean_Patch_v1.01.zip`에 넣으면 그 파일을 씁니다.
- **진행률이 멈춘 것 같음**: 본편 패치가 3GB 파일을 다시 쓰기 때문에 몇 분 걸립니다. CIA 변환까지 하면 복호화·복사가 한 번 더 붙습니다. 디스크가 느리면 더 걸립니다.

## 개발

```powershell
# 실행 (파이썬 3.10+)
python .\yw3ko_patcher.py

# 핵심 기능 점검 (xdelta3 내려받기, 패치 추출, 적용/실패 처리, GUI 생성)
python .\tools\smoke_test.py

# 배포 exe 자체 점검 (다운로드·압축 해제·지문 확인)
.\dist\YW3-KO-Patcher.exe --selftest "$env:TEMP\yw3_selftest.log"

# 단일 exe 빌드 -> dist\YW3-KO-Patcher.exe
pwsh -File .\build.ps1
```

- `yw3ko_patcher.py` : GUI와 패치 로직 (표준 라이브러리만 사용)
- `yw3convert.py` : CIA/NCCH → CCI 변환, CIA 복호화, 암호화 CCI(NCCH AES-CTR) 복호화, keys.txt/seeddb.bin 읽기 (AES는 Windows CNG `bcrypt.dll` 사용, 외부 패키지 없음)
- `yw3profile.py` : 공식 패치 manifest의 원본 영역 크기/해시 (키나 게임 데이터는 없음)
- `tools/make_icon.py` : `build/app.ico` 생성
- `tools/smoke_test.py` : 스모크 테스트 (가짜 CIA/NCCH로 변환·왕복 검증 포함)
- `build.ps1` : PyInstaller 단일 exe 빌드

xdelta3는 GPL 라이선스 도구라서 저장소에 넣지 않고, 공식 3.2.2 배포본을 지문 확인 후 내려받습니다.
